## 2. 关键教训：这次是**被 revert 亲手拆掉的**

git 事实（`git reflog` + `git show`）：

| 时间 | 事件 |
|---|---|
| 15:00:35 | `c141012 feat(samples): 面板功能测试示例（计数器 / 输入同步）` —— demo 放在 `Assets/Zipper/Samples/UI/`（**白名单内，可入库**） |
| 之后 | `reset --hard HEAD~1` 把 `c141012` **丢掉**（仅存于 reflog），demo 最终落在 `Assets/Script/`（白名单外） |
| 15:48:16 | `b658eab fix(ui): 层级根不再依赖场景引用…` —— **同一提交里顺手加了 demo 的注册**（`builder.Register<CounterViewModel/SyncViewModel>` + 两条 `RegisterPanel`）与 `ZPanelRoot.CreateRuntime()`、`gameObject.scene.IsValid()` 校验 |
| 15:51:53 | `d23b6b5` / `47102c4` 两个 revert → **注册与层级根修复一起被撤**，而 demo 脚本 / 场景 / prefab / Addressables 配置都在库外原封不动 → 表现为"代码都在，怎么就坏了" |

**两条教训**：

1. **框架侧提交不要夹带业务 demo 的接线** —— 否则一 revert 就连坐；demo 的接线应留在 demo 自己的文件里（或按 `agent-role.md` 由使用者持有）。
2. demo 想免于被误伤，只能放进 `Assets/Zipper/`（白名单内，如 `c141012` 那样）；**不能**用 `git add -f` 强加（`git-workflow.md` §1 明令禁止）。

⚠️ **附带发现（重要）**：`b658eab` 的 `ZPanelRoot.CreateRuntime()` **自己也没管 Canvas** —— 它在场景根 `new GameObject("ZPanelRoot")` 后直接挂 5 个普通 `Transform` 子节点，既不在 Canvas 下、层级父节点也不是铺满的 RectTransform。**即便那次修复没被 revert，面板依然画不出来（坑 3）**。若当时"改了还是看不见"是 revert 的动因，根因就在这条。
