## 2. 本期定案（事件总线，v0.5 / v0.5.1）

| 事项 | 结论 |
|---|---|
| 事件类型约束 | **必须引用类型**（`where T : class`）。原"不加约束、载荷优先 `readonly struct`"**作废**；代价：每次发布需一个事件对象（总线自身仍零分配）；**struct 事件不支持** |
| 状态查询 | **`ZEventsState GetState()`** 取代 `SubscriberCount<T>()`；DTO 照对象池（`ZPoolState`/`ZPoolsState`）形状：`Type EventType`、`{ get; private set; }`、`TotalSubscribers` 必须 `+=` 累加 |
| 命名统一 | `recipient` → **`subscriber`**；`UnregisterAll` → **`UnsubscribeAll`**（代码与文档同一个词） |
| 收件人为 null | `UnsubscribeAll(null)` → **记 Warning 并忽略**（不抛）：既防误清匿名订阅，又不给关闭期路径添异常 |
| 反向边（凭据→通道） | `Subscription` **持有所属通道**，Dispose 只标记、**摘除由通道完成**；通道必须提供 `Remove(Subscription<T>)`（按身份），否则 `Remove(this)` 会被绑到 `Remove(object)` 而**静默删不掉** |
| `Remove(...)` 契约 | 三个重载都返回**移除个数**（`int`），上层据此 `true` / "Warning + false" —— 避免**未命中却谎报成功** |
| 批量释放 | `EventChannel.Dispose()` 用"一次性 `Array.Empty` + 逐个只标记"（O(n)）；`Remove` 用"复制 + 替换引用"（`Array.Resize`/`Array.FindAll` 本质都是 copy-on-write） |
| 关闭期语义 | `_disposed` 门：Dispose 后 `Publish` no-op；`Subscribe` 返回**共享空凭据**（`EmptyIDisposable`），绝不返回 null |
| 主线程校验 | 总线自持线程 ID（ctor 捕获）；`Subscribe`/`Publish`/`Unsubscribe`/`UnsubscribeAll` 入口校验，违规记 Error 并忽略；**不复用日志的 dispatcher**（三条耦合理由见 §4.2） |
| 不采纳（对照 CommunityToolkit.Mvvm） | class 信封（`MessageBase`/`ValueChangedMessage<T>`）、弱引用订阅、请求-应答、MVVM 值变化语义、`IRecipient` 声明式注册、静态 `.Default` 单例 —— **一律不采纳**（逐条理由在附录 A） |
| 不做 `this` 自动装配 | 基类 / 扩展方法 receiver / 反射发现三条路全不做；留"扩展方法 + 空标记接口"作为将来 10 行可选项（附录 B） |
| 通道 token | **延后**（同一事件类型多通道），等真实需求 |

## 3. 验收证据（事件总线）

用临时 harness（Core 源码 + 测试 `Main` 编进同一 exe，直接跑真实 `ZEventBus`，含假 `IZLogger` 记录日志调用；产物在 `Library/` 内、跑完即删）：

```
ALL PASS（19 项）—— 关键项：
  状态计数 TotalSubscribers / 按类型计数 / EventType 是 Type ✓
  凭据 Dispose 真正摘除（计数 2→1）✓
  快照语义：回调内退订自己、回调内订阅同类型 ✓
  异常隔离：其余仍收到 + 记 Error ✓
  主线程校验：非主线程 Publish 不派发 + 记 Error；非主线程 Subscribe 返回非 null 空凭据 ✓
  Publish 无人订阅：不记任何日志 ✓
  Unsubscribe 三情形：命中 true / 未命中 false+Warning / 无该类型通道 false+Warning ✓
  Subscribe(null handler) 抛 ArgumentNullException ✓
  UnsubscribeAll(null) 不误清匿名；UnsubscribeAll(owner) 只清该收件人 ✓
  关闭期：Dispose 后不抛、Subscribe 被拒绝、GetState 为空、Dispose 幂等 ✓
  规模：5000 个订阅的通道 Dispose 耗时 0ms（O(n²) 那版会明显慢）✓
```

## 4. 我犯过并已更正的错误（方法论留痕）

| 错误 | 更正 |
|---|---|
| 断言"`R3.Unity` 未装" | **错**——只查了 NuGet 的 core DLL，没看 UPM 包。实际 `Packages/manifest.json` 里 `com.cysharp.r3` 已装（1.3.1，与 core 一致）。已更正 `event-bus-design.md` v0.2 |
| 建议"避免原地 `Array.Resize`" | **错**——`Array.Resize` 本就是"新数组 + 复制 + 替换字段"= copy-on-write。v0.5.1 撤回 |
| 文档写"两参重载 `subscriber` 为 null → 抛" | **错**——`subscriber = null` **就是匿名订阅**（单参重载正是这么调的），合法。v0.5.1 更正 |
| 验收观测项选错 | 曾用"恒为 0 的 `TotalSubscribers`"当证据判断 `UnsubscribeAll(null)` 是否误清；换成按类型计数后重测才成立。**教训：证据的观测项本身必须先验证** |
| 检查写弱导致假 PASS | "Dispose 后 Subscribe 应被拒绝"一条，曾把新凭据 `Dispose` 掉之后才计数 → 假 PASS；改成"拿到后不 Dispose 再计数"才暴露问题 |
